# Node to Rust Backend Migration Plan

The backend (four Fastify services and the TypeScript `common/*` packages) moves to Rust. Frontends, mobile, CMS and automation are unchanged. File structure and engineering practices stay the same; only the language and framework change.

## Decisions

| Topic | Decision |
|---|---|
| HTTP framework | Axum on Tokio with tower and tower-http |
| Validation | serde with `deny_unknown_fields` plus `validator`, through a `ValidatedJson<T>` extractor that returns the existing field-level 400 envelope |
| Database | SQLx for Postgres with runtime-checked static queries and `FromRow` models (no offline query data to maintain) |
| Migrations | `sqlx migrate`, SQL files in `common/database/migrations`, executed by `admin-api migrate` in the `migrate` compose service |
| OpenAPI | Not yet implemented. Convention recorded in `.claude/instructions/openapi.instructions.md` (utoipa with swagger-ui outside production) |
| Cutover | Big bang: all four Node services and the TypeScript common packages were removed once the Rust services passed their tests and an end-to-end run |
| Crate naming | `ru5ty-gate-<name>` (slug substitution done across the repo) |
| GraphQL | Flattened to `async-graphql` resolvers that call the downstream services |

## Practices carried over

| Node rule | Rust equivalent |
|---|---|
| No `any`, no `@ts-ignore` | `unsafe_code = forbid`; clippy denies `unwrap_used`, `expect_used`, `panic`, `todo`, `unimplemented`, `dbg_macro` |
| No comments | Unchanged |
| Functions, not arrow functions | Named `fn`; closures only inside iterator adapters |
| Class controllers and services | `struct` with `impl`, private fields, `pub(crate)` |
| One item per file | Unchanged, with `mod.rs` or a `lib.rs` re-export per folder |
| Typecheck, lint, format gates | `cargo check`, `cargo clippy -D warnings`, `cargo fmt --check`, chained into `pnpm typecheck`, `pnpm lint`, `pnpm format:check` |
| Service tests in `tests/services` | `#[sqlx::test]` against Postgres; only email, Redis and SMS are mocked |

## Behaviour changes and hardening made during the port

| Area | Change |
|---|---|
| Logout | Per-user `minIat` cutoff is `now + 1` so same-second tokens are revoked without blocking an immediate re-login |
| Webhooks | SSRF protection (`TargetPolicy::PublicOnly` in production) on subscription save and on delivery; redirects are never followed |
| CSV export | Text cells beginning with `=`, `+`, `-`, `@`, tab or carriage return are prefixed with `'` |
| GraphQL | Depth limit 10 and complexity limit 200; introspection and playground forced off in production |
| Validation | Field names in 400 responses are camelCase for multi-word fields |
| Errors | 5xx responses are reported to Sentry from `AppError::Internal`; panics become 500 responses (release profile keeps unwinding) |
| Admin bootstrap | Locked by a row-level `FOR UPDATE` on `system_bootstrap` so concurrent calls cannot create two admins |

## Known gaps

- OpenAPI/Swagger UI is not generated by the Rust services; `docs:export` and `docs:site` were removed with the Node scripts
- OTLP log and trace export to OpenObserve is not ported; logs are JSON on stdout
- Azure Blob storage is not supported by `common/storage`
- Docker images have not been built or run end to end; CI builds them on the next push to `main`
- Request validation reports the first serde type error per request (serde stops at the first failure)
- `schedule-api` should run as a single replica until delivery rows are claimed with `FOR UPDATE SKIP LOCKED`

## Coexistence

There is none any more. The backend and `common/` are a pure Cargo workspace; `pnpm-workspace.yaml` lists only the frontend and mobile apps.
